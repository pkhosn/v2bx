# HY2 端口跳跃（默认关闭）

管理菜单「HY2 端口跳跃」提供开启、状态、关闭。独立命令为
`/usr/local/V2bX/V2bX hy-hop`。当前支持 Linux、systemd、nftables，
且 V2bX 的目标 UDP 端口明确监听在 `0.0.0.0`。双栈及 IPv6 监听需手动配置。

输入 HY2 当前监听端口、跳跃范围（1024–65535、最多 1000 个端口）。
原端口保持不变，范围不可包含目标端口或已占用的 UDP 端口。
需要 root 以及 `nft`、`ss`、`systemctl`。范围也必须在云安全组/上游防火墙放行。
菜单不修改其他防火墙，不保证云侧自动放行；已有 NAT/容器规则需自行检查。

规则仅写入独立 nft 表 `inet v2bx_hy_hop`，以重定向方式将新端口映射到
原监听，并限制为目标地址属于本机、连接原始方向的 IPv4 UDP 流量，
排除本机出站 UDP 的响应报文。
`/etc/V2bX/hy-port-hop.nft` 与 `V2bX-port-hop.service` 用于开机恢复。
关闭只删除专属规则和服务文件，保留原 HY2 监听。关闭会中断跳跃连接。
当前只管理一个端口范围；多个节点需手动分配互不重叠范围。
如果面板修改实际监听端口，必须关闭并重新设置映射。

客户端必须收到同一跳跃端口范围：sing-box 使用 `server_ports`，
mihomo 使用 `ports`，原生 Hysteria2 使用服务器多端口语法。
建议先采用 30 秒跳跃间隔；试验可短于该值以覆盖多次切换。
单端口客户端继续可用。通过中转时，中转入口也必须支持对应 UDP 范围转发。

验证时应同时测试单端口与多端口连接，持续时间覆盖多次跳跃；检查
`nft list table inet v2bx_hy_hop` 计数增长及实际代理请求，不能只检查 UDP
监听（重定向端口本来不会分别显示为进程监听）。

端口跳跃可改善单端口受干扰时的可用性，无法隐藏服务器 IP，也不能防止
IP 封禁或整条线路限制 UDP。不要把端口跳跃等同于抗封锁保证。
