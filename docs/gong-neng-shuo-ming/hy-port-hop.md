# HY2 节点向导与端口跳跃

端口跳跃整合在节点配置向导中，不再提供独立管理菜单。
首次安装、菜单 **15 重新生成配置**、菜单 **17 追加节点**均使用同一流程。
HY2 节点支持独立 hysteria2 内核和 sing 内核。

## 新增节点

1. 按原流程填写面板、节点 ID、内核与证书信息。
2. 向导显示面板的实际 UDP 监听端口。
3. 面板提供跳跃范围时，显示范围并询问是否自动配置，默认同意。
4. 面板未提供时，选择“不启用”或“手动填写范围并自动配置”。手动范围必须与客户端订阅一致，不会猜测范围或自动修改面板。
5. 填写完所有节点后，向导检查并配置规则及开机恢复服务，再保存节点配置。失败保留输入，可修复工具/端口等问题后输入 `1` 重试，或取消。

例如实际监听 `36005`、订阅跳跃范围 `40000-40009`，向导配置
`UDP 40000-40009 → 36005`。原端口仍可直接使用，跳跃端口不需要分别由进程监听。
若拒绝配置，但客户端仍使用跳跃范围，则客户端依然无法连接；必须同步修改面板订阅。

## 已有节点调整或关闭

进入菜单 **17 追加节点**，输入已有 HY2 节点的面板与节点 ID，选择
“仅调整端口跳跃”。原节点、内核、证书和其他自定义字段保留，不重复申请证书。
可以改用面板范围、手动填写新范围，或关闭该节点的映射。
旧菜单生成的有效 IPv4 单范围规则会被识别；修改某个节点时保留其他节点的旧映射。

每个节点支持一个连续范围，多个节点可配置互不重叠的范围。
范围限制为 1024–65535、最多 1000 个端口，不能覆盖任何已配置的跳跃目标监听端口，
也不能使用已被本机进程占用的 UDP 端口。仅支持明确的 `0.0.0.0` IPv4 监听；
已有节点开启时还会核对运行中的 V2bX 监听。IPv6/双栈需另行规划。

## 面板接口

后端节点接口的 `server_port` 始终表示实际监听端口，不能替换为范围。
向导兼容可选的 `mport` 或 `port` 字段，例如：

```json
{
  "server_port": 36005,
  "port": "40000-40009"
}
```

优先使用 `mport`，其次使用包含范围的 `port`；单个连接端口不视为跳跃范围。
旧面板仅返回 `server_port` 时仍可手动配置。
现有 V2Board 接口补充说明见 [面板字段说明](../hy-hop-panel-api.md)。
面板以后修改监听端口或范围，需要再次运行节点向导更新规则；本版不自动随后台轮询修改防火墙。

## 规则、持久化与失败处理

复用专属 nft 表 `inet v2bx_hy_hop`、`/etc/V2bX/hy-port-hop.nft` 和
`V2bX-port-hop.service`。映射保存在节点的 `PortHop` 向导元数据中，
应通过向导修改，运行时内核不会单独根据该字段创建规则。
服务在 V2bX 之前恢复规则；原服务失败后的残留表会在本服务启动时清理重建。

需要 root、Linux、systemd 与 nftables；缺少工具时会报错并允许安装后重试。
不会关闭防火墙、清空宿主机规则集或自动操作云安全组。
**服务器商的安全组和上游防火墙须允许客户端使用的 UDP 范围。**

取消向导或输入中断不保存配置、不新增规则。规则应用失败会恢复之前的文件、服务状态和专属表；
节点配置保存失败也回滚映射。回滚失败会明确报错并停止，不能继续当作配置成功。
重新生成全部节点时会移除被替换节点的映射；追加或编辑时保留其他节点。
外来文件、同名但不属于本功能的表、未知规则内容均拒绝覆盖。

## 本地验证

使用既有 Go 测试框架，构建标签与项目一致：

```bash
GOEXPERIMENT=jsonv2 go test -tags 'sing xray hysteria2 with_quic with_grpc with_utls with_wireguard with_acme with_gvisor' ./cmd ./api/panel -count=1 -timeout=120s
bash -n script/V2bX.sh script/initconfig.sh
```

`TestHopKernelRedirection` 在 root 且具备 `unshare`、`nsenter`、`ip`、`nft`、`python3` 的本机环境中，
使用私有网络命名空间实际验证两个目标监听、四个跳跃端口和规则重建后的 UDP 转发；
不创建宿主机接口或修改宿主机防火墙。缺少这些条件会跳过该测试，不能把跳过当作内核转发已验证。
其余测试模拟 systemd/nft 操作以验证事务提交、保存失败回滚、应用失败回滚、旧规则迁移和多节点保留。

端口跳跃无法隐藏服务器 IP，也不能防止 IP 封禁或整条线路限制 UDP。
